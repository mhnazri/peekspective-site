PeekLens Mobile Privacy Policy

Product-specific privacy notice for PeekLens Mobile.
Last updated: 20 September 2026

This policy applies to the iOS version of PeekLens Mobile made available by Peekspective — the current, EDIFACT-focused app. "PeekLens Mobile" is presently a working product name, and PeekLens may in the future become a broader product family covering additional EDI standards; this policy is scoped to the present app and does not automatically extend to any future PeekLens product.

Overview

PeekLens Mobile is an offline, syntax-only UN/EDIFACT message inspection tool built for EDI professionals, consultants, implementers, and support teams. This policy describes, factually and specifically, what PeekLens Mobile does and does not do with your data, based on the app's actual implementation as of the last updated date above.

In short: PeekLens Mobile does not transmit your EDI message content to external servers. Messages you paste, import, or receive for inspection are processed locally on your device, unless you explicitly choose to share or export content yourself. Read on for the specifics.

The EDI messages and files you work with

When you paste, type, import, or share an EDIFACT message into PeekLens Mobile for inspection:

  • The message is processed entirely on your device. PeekLens Mobile does not send message content to any server operated by us or by any third party.
  • There is no backend or cloud processing step involved in inspecting, validating, explaining, comparing, or redacting a message — all of this happens locally, using data bundled with the app (the UN/EDIFACT reference directory) and your device's own processing.
  • If you import a file using the system file picker, PeekLens Mobile reads the file you select and does not initiate any upload of it anywhere. (If the location you choose in the file picker happens to be a cloud-linked folder you've set up yourself in iOS — for example iCloud Drive — that's a transfer between your device and your own cloud provider, governed by their own terms, not something PeekLens Mobile initiates or has visibility into.)
  • If you use iOS's share sheet to send a message into PeekLens Mobile from another app, that handoff happens entirely on-device (via an iOS App Group container shared between PeekLens Mobile and its Share Extension) — no network transfer is involved.

History (optional, off by default)

PeekLens Mobile includes an optional local history feature that you can turn on if you want a record of past inspections.

  • Off by default. History is not recorded unless you explicitly enable it in the app.
  • Metadata only — never your message content. When enabled, history stores things like the timestamp, message type, EDIFACT release, error/warning counts, and any note or bookmark you add. It does not store the raw EDIFACT message you inspected.
  • Encrypted at rest. History entries are stored using iOS's secure, encrypted on-device storage (Keychain-backed), not as a plain, unprotected file.
  • Stays on your device. History is never transmitted anywhere. It exists only on the device where it was created.
  • You can delete it at any time. The app provides a way to clear all history whenever you choose. Use the app's own clear-history function when you want to remove it — like other apps that use iOS's secure Keychain storage, simply uninstalling PeekLens Mobile is not guaranteed to delete this data immediately, since iOS Keychain storage can persist independently of the app itself.

Masking / redaction

PeekLens Mobile's message redaction feature — for hiding sensitive values (like party names or reference numbers) before sharing a message with a colleague for troubleshooting — works entirely in memory on your device. It reads the message you're already viewing, looks up field definitions from the bundled reference directory, and produces a masked version for you to copy or export. Nothing is stored or transmitted as part of this process beyond what you, the user, then choose to do with the result (e.g. sharing it yourself via iOS's share sheet).

App settings

A small number of app preferences (such as your chosen theme and whether history is enabled) are stored locally on your device using standard iOS app-preference storage. These settings are never transmitted anywhere.

What PeekLens Mobile does NOT do

As of the last updated date above, and based on the app's actual code:

  • No analytics SDK of any kind is included in the app.
  • No crash-reporting or telemetry SDK of any kind is included in the app.
  • No third-party advertising SDK is included in the app.
  • No third-party tracking SDK is included in the app.
  • No runtime network requests are made by the app to any server, ours or otherwise.
  • No sensitive device permissions (camera, microphone, location, contacts, photo library) are requested by the app, because none of PeekLens Mobile's features require them.

In-app purchases

The current version of PeekLens Mobile does not include in-app purchase functionality. If in-app purchases are introduced in a future version, purchases will be processed entirely through Apple's own App Store / StoreKit infrastructure — we would not receive or process your payment card details directly, as Apple handles that in accordance with Apple's own Privacy Policy. This policy will be updated to reflect that functionality's actual data handling before or when it becomes available.

Children's privacy

PeekLens Mobile is a professional tool intended for EDI/EDIFACT practitioners and is not directed at, or intentionally marketed to, children. We do not knowingly collect data from children.

Changes to this policy

If PeekLens Mobile's data practices change in the future — for example, when in-app purchase functionality is added — this policy will be updated to reflect that accurately, and the last updated date above will be updated accordingly. We encourage checking this page periodically.
